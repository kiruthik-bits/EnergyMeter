## Purpose

The primary goal of this script is to provide a testing environment for validating the MQTT-to-database pipeline. It is designed to work with test data streams, such as those generated by a dummy ESP8266 device or other MQTT publishers.

This Python script (`mqtt_data_to_db.py`), located in the `Test` directory, acts as an MQTT client primarily for testing purposes. It subscribes to a specific MQTT topic (defaulting to `"sensors/power/dummy"`) where power data is expected to be published (e.g., by a test ESP8266 device or another MQTT publisher). Upon receiving a message, it parses the JSON payload, validates the data, and stores it into the shared SQLite database file (`../../power_data.db`).

It mirrors the functionality of the main logger script (`../receive_mqtt_store_db.py`) but is intended for use with test data streams or during development.

---

## Features

*   Connects to an MQTT broker.
*   Subscribes to a specified topic (defaults to a test topic).
*   Receives JSON payloads containing power data.
*   Parses and validates incoming data fields (`reporterDeviceId`, `sourceDeviceId`, `timestamp`, `power`).
*   Attempts to convert ISO8601 timestamps to Unix epoch format for efficient querying, storing `NULL` if conversion fails.
*   Stores validated data into the `power_data.db` SQLite database located in the `RPI` directory.
*   Uses database transactions (ACID principles) for reliable writes.
*   Handles potential JSON errors and database errors gracefully.
*   Includes graceful shutdown on receiving termination signals (Ctrl+C, SIGTERM).
*   Uses Write-Ahead Logging (WAL) for SQLite for improved concurrency.

## Prerequisites & Setup on Raspberry Pi

1.  **Hardware:** Raspberry Pi or similar Linux system.
2.  **Python 3:** Verify installation with `python3 --version`.
3.  **Paho MQTT Client Library:** Install via pip:
    ```bash
    pip3 install paho-mqtt
    ```
4.  **MQTT Broker:** An MQTT broker (like Mosquitto) must be running and accessible.
    *   **Installation (Mosquitto):**
        ```bash
        sudo apt update
        sudo apt install mosquitto mosquitto-clients -y
        sudo systemctl enable mosquitto.service
        sudo systemctl start mosquitto.service
        ```
    *   **Verification:** `sudo systemctl status mosquitto.service`
    *   **Note:** By default, Mosquitto runs on port 1883 without authentication. Configure authentication for production.
5.  **SQLite3:** The Python `sqlite3` module is typically included with Python 3.

## Configuration

Modify the constants within `mqtt_data_to_db.py` as needed:

*   `MQTT_BROKER_HOST`: Address of your MQTT broker (default: `"localhost"`).
*   `MQTT_BROKER_PORT`: Port of your MQTT broker (default: `1883`).
*   `MQTT_TOPIC`: Topic to subscribe to (default: `"sensors/power/dummy"`). **Ensure this matches your test publisher.**
*   `MQTT_CLIENT_ID`: Unique ID for this script (default: `"rpi-db-logger"`).
*   `MQTT_USER`, `MQTT_PASSWORD`: Credentials if your broker requires authentication (default: placeholders).
*   `DATABASE_FILE`: Path to the database. Automatically calculated as `../../power_data.db` (in the `RPI` directory).

## Functionality Explained

### MQTT Roles

*   **Broker:** Central message hub (e.g., Mosquitto running on the RPi).
*   **Publisher:** Client sending messages to a topic (e.g., a test ESP8266 or script publishing to `sensors/power/dummy`).
*   **Subscriber:** Client receiving messages from a topic (this script, `mqtt_data_to_db.py`).

### Connection Workflow

1.  This script connects to the MQTT broker.
2.  Upon connection, it subscribes to `MQTT_TOPIC`.
3.  A separate publisher sends JSON messages to the same `MQTT_TOPIC` on the broker.
4.  The broker forwards these messages to this script.
5.  The `on_message` callback in this script processes the received message.

### Database (`power_data.db`)

*   **Location:** The script writes to `../../power_data.db`.
*   **WAL Mode:** Enabled (`PRAGMA journal_mode=WAL;`) for better concurrency and durability.
*   **Schema (`power_readings` table):**
    *   `id`: Auto-incrementing primary key.
    *   `reporter_device_id`: ID of the publishing client (TEXT, NOT NULL).
    *   `source_device_id`: ID of the measured device/sensor (TEXT, NOT NULL).
    *   `timestamp_iso`: Original timestamp string from payload (TEXT, NOT NULL).
    *   `timestamp_unix`: Timestamp converted to Unix epoch seconds (REAL, NULLable). Indexed for performance.
    *   `power_watts`: Power reading (REAL, NOT NULL).
    *   `received_at`: Timestamp when the record was inserted by this script (TIMESTAMP, NOT NULL, DEFAULT CURRENT_TIMESTAMP).

### Data Processing & Validation (`on_message`)

1.  Decodes payload to UTF-8 string.
2.  Parses string as JSON.
3.  Extracts required fields safely.
4.  Validates field presence and numeric conversion of `power`.
5.  Attempts `timestamp` conversion using `parse_iso_to_unix`.
6.  If valid, prepares data for insertion.

### Error Handling

*   **MQTT Connection:** Paho library handles auto-reconnect; logs disconnects.
*   **Invalid Messages:** Logs warnings and skips messages that are not valid JSON, missing fields, or have invalid `power` values.
*   **Database Writes:** Uses transactions (`BEGIN`/`COMMIT`/`ROLLBACK`) for atomicity. Catches `sqlite3.Error`, logs it, and rolls back the transaction to maintain consistency. WAL mode enhances durability.
*   **Shutdown:** `signal_handler` ensures graceful shutdown on `SIGINT`/`SIGTERM` by stopping the MQTT loop, disconnecting the client, and closing the database connection.

## How to Run

1.  Ensure prerequisites are met and the MQTT broker is running.
2.  Modify configuration constants in `mqtt_data_to_db.py` if needed (especially `MQTT_TOPIC` if not using the default dummy topic).
3.  Open a terminal on your Raspberry Pi.
4.  Navigate to the `MQTT/Test/` directory:
    ```bash
    cd /path/to/EnergyMeter/RPI/MQTT/Test/
    ```
5.  Run the script:
    ```bash
    python3 mqtt_data_to_db.py
    ```
6.  The script will log connection status and received messages.
7.  Press `Ctrl+C` to stop the script gracefully.

You can inspect the data written to `../../power_data.db` using command-line tools (`sqlite3 ../../power_data.db`) or GUI tools like DB Browser for SQLite.
